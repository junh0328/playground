# 과제 평가 상세 체크리스트

## 0. 코드 적정성 (Over-Engineering 체크) - 최우선 확인

### 불필요한 코드 여부
```
[ ] 요구사항에 명시되지 않은 기능을 과도하게 구현하지 않았는가?
[ ] 중복 정의된 상수/타입이 없는가? (여러 파일에 같은 상수 정의)
[ ] 파일 1개뿐인 폴더에 index.ts 배럴 파일을 만들지 않았는가?
[ ] 인라인으로 충분한 설정을 별도 파일로 분리하지 않았는가?
[ ] 10줄 미만의 로직을 별도 커스텀 훅으로 분리하지 않았는가?
[ ] 요구사항에 없는 접근성(ARIA) 코드가 과도하게 포함되지 않았는가?
[ ] Skeleton UI가 과하게 상세하지 않은가? (간단한 로딩으로 충분한 경우)
```

### 폴더 구조 적정성
```
[ ] 폴더 하나에 파일 1개만 있는 패턴이 반복되지 않는가?
[ ] 일관된 구조인가? (어떤 폴더는 4개, 어떤 폴더는 1개 → 비일관)
[ ] 프로젝트 규모에 맞는 구조인가?
    - 소규모 (파일 10개 미만): components/, hooks/ 정도면 충분
    - 중규모 (파일 10-30개): 도메인별 분리 가능
    - 대규모 (파일 30개+): 세분화된 구조 허용
[ ] 불필요한 depth가 없는가? (components/Button/Button.tsx 대신 components/Button.tsx)
[ ] queries/ 또는 constants/ 폴더에 파일 1개만 있지 않은가?
```

### 프레임워크 활용도 (Next.js인 경우)
```
[ ] 서버 컴포넌트를 활용할 수 있는 곳에 활용했는가?
[ ] 모든 컴포넌트가 'use client'로 시작하지 않는가?
[ ] API Routes를 활용할 기회가 있었는데 사용하지 않았는가?
[ ] 적절한 렌더링 전략을 선택했는가? (SSR/SSG/CSR)
    - 정적 데이터 → SSG
    - 사용자별 데이터 → SSR 또는 CSR
    - 실시간 데이터 → CSR + React Query
    - SEO 필요 → SSR 또는 SSG
[ ] next/image를 활용했는가? (이미지가 있는 경우)
```

### API 활용 방식 (Mock API 제공 시)
```
[ ] 서버가 제공하는 필터링 기능을 활용했는가? (?status=value)
[ ] 서버가 제공하는 정렬 기능을 활용했는가? (?_sort=field&_order=desc)
[ ] 서버가 제공하는 페이지네이션을 활용했는가? (?_page=1&_limit=20)
[ ] 총 개수를 서버 응답(헤더 등)에서 가져오는가? (클라이언트 계산 X)
[ ] 클라이언트에서 filter(), sort()로 재구현하지 않았는가?
```

**주의**: 클라이언트 처리가 항상 틀린 건 아님. 요구사항과 데이터 규모에 따라 판단.
